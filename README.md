# Rich Tour Sanity Studio

## Цены выезда и размещения

Все цены — стоимость всего тура за одного человека в евро. Базовая цена выезда
редактируется отдельно от цен отелей. Под переключателем «Діє знижка раннього
бронювання» появляются необязательная ранняя цена и общий срок «Раннє бронювання до»
(включительно). Выключение скрывает оба поля и ранние цены отелей, но не удаляет
значения. При включённом переключателе ранняя цена должна быть неотрицательной
и меньше обычной. Если ранняя цена задана у выезда или хотя бы одного отеля,
срок обязателен; он не может быть позже даты начала тура. Скрытые значения
при выключенном переключателе не блокируют публикацию.

У отеля одна обычная и одна необязательная ранняя цена, а также необязательное поле
«Варіант розміщення», например «Проживання в котеджі стандарт». При добавлении
отеля обе цены копируются из текущей формы выезда, включая сохранённую скрытую
раннюю цену. Описание остаётся пустым. Последующее изменение базовых цен не меняет
отели. Дублирование отеля сохраняет его собственные цены и описание.

Сайт пока читает только обычные поля `price`: новые ранние цены, описание
размещения и автоматическое переключение по сроку требуют отдельного изменения сайта.

Проверки цен и миграции:
`node --test components/tourPricing.test.cjs components/tourPricing.integration.test.cjs scripts/hotel-prices.test.cjs`.

### Одноразовая миграция обычных цен отелей

Миграция `copy-tour-price-to-hotels` заменяет обычную цену каждого отеля базовой
ценой его выезда, **в том числе ранее настроенные индивидуальные цены**.
Опубликованные документы и черновики обрабатываются независимо. Новые поля
не заполняются миграцией; остальные данные не изменяются. Документы без корректной
неотрицательной базовой цены или без уникальных `_key` отелей пропускаются и попадают
в отчёт. Совпадающие цены не патчатся.

Сначала войдите в Sanity CLI (`npx sanity login`). На время подготовки и применения
приостановите редактирование выездов. Проверьте выбранные project/dataset в
`sanity.cli.ts` и переменных окружения. Следующие команды PowerShell используют
один и тот же текущий project/dataset:

```powershell
npx sanity exec scripts/hotel-price-migration.ts --with-user-token -- prepare --file migration-backups/hotel-prices-before.json
$env:HOTEL_PRICE_MIGRATION_BACKUP = (Resolve-Path migration-backups/hotel-prices-before.json).Path
npx sanity migration run copy-tour-price-to-hotels --dry-run
# После проверки отчёта и пробных патчей:
npx sanity migration run copy-tour-price-to-hotels --no-dry-run
```

Подготовка ничего не меняет в Sanity: сохраняет полные исходные документы и отчёт
с количеством документов, отелей, замен и списком пропусков. Файл не перезаписывается;
для новой подготовки выберите другое имя. Каталог `migration-backups` исключён из Git.
Сохраните копию до завершения проверки миграции. Миграция требует эту копию,
проверяет project/dataset и ревизии документов, а патчи защищены от конкурентного
редактирования. При конфликте исправьте причину и подготовьте новую копию,
сохранив предыдущую для отката уже выполненных изменений.

После применения запустите `prepare` с **новым** именем файла: в отчёте должно
остаться ноль замен для корректных документов. Миграция опубликованных документов
меняет опубликованные цены сразу; изменение черновика не публикует его.
Не запускайте миграцию повторно после настройки индивидуальных цен отелей.

Для восстановления сначала просмотрите отчёт, затем выполните ту же команду с `--apply`:

```powershell
npx sanity exec scripts/hotel-price-migration.ts --with-user-token -- restore --file migration-backups/hotel-prices-before.json
npx sanity exec scripts/hotel-price-migration.ts --with-user-token -- restore --file migration-backups/hotel-prices-before.json --apply
```

Восстановление меняет только цены, затронутые миграцией, по `_key`, включая удаление
поля, если изначально его не было. Остальные данные сохраняются. Удалённые отели
и цены, изменённые после миграции, считаются конфликтами: при наличии конфликтов
запись не начинается. Каждая запись защищена текущей ревизией; при конфликте во
время записи процесс остановится, уже восстановленные цены можно безопасно
пропустить при повторном запуске.

## Видео в описании отеля

В кратком и полном описании отеля доступны блоки «Відеофайл» и «YouTube».
Их можно добавлять между абзацами и переставлять. Для YouTube вставьте HTTPS-ссылку
на ролик (`watch`, `youtu.be`, `shorts`, `embed`) или код iframe. Сохраняется только
идентификатор видео; параметры плеера и HTML не сохраняются.

Видеофайлы загружаются в Sanity: MP4 до 100 000 000 байт включительно.
Подготовьте H.264/AAC заранее; конвертация и создание обложек не выполняются.
Название и обложка файла необязательны. Размер и MIME-тип проверяются до загрузки,
а выбранный asset проверяется перед публикацией. Текст в обоих описаниях обязателен.

У одного отеля краткое описание с видео отображается на странице тура.
При нескольких отелях кнопка «Відео» в карточке открывает видео краткого описания
перед полным описанием в окне отеля. Видео полного описания доступны в этом окне
для обоих вариантов. Плееры не запускаются автоматически; закрытие окна останавливает
просмотр, повторное открытие начинает его заново.

Для выпуска сначала обновите сайт, затем Studio. Миграция документов и новые
переменные окружения не нужны. Проверка правил видео:
`node --test components/hotelVideo.test.cjs`.

## Предпросмотр выезда на сайте

В документе «Тур на конкретну дату» администратор может нажать «Подивитися на сайті».
Для этого задайте `SANITY_STUDIO_SITE_URL` как полный адрес сайта (локально
`http://localhost:3000`) и пересоберите Studio. На сайте должны быть заданы
`PREVIEW_SESSION_SECRET` и серверный Sanity-токен с доступом
к черновикам. Studio использует вход по токену; после обновления сотрудникам
потребуется войти повторно. Предпросмотр показывает последнюю сохранённую версию
выезда, включая неполные документы.

Для production адрес `https://rich-tour.vercel.app` задан в `.env.production` Studio.
При сборке другого окружения задайте `SANITY_STUDIO_SITE_URL` в его настройках и
пересоберите Studio. На проекте сайта в Vercel отдельно задайте `SANITY_API_TOKEN`
и `PREVIEW_SESSION_SECRET` (не менее 32 символов) для Production и, если нужен
предпросмотр на тестовых деплоях, для Preview. Локальный `.env.local` в Vercel
не передаётся. После изменения переменных сайта создайте новый деплой.

Studio содержит три workspace в одном репозитории:

- `/content` — туры, категории туров и страны из dataset `production`, доступны всем сотрудникам Studio;
- `/site` — настройки сайта и остальной публичный контент из dataset `production`, видны только суперадминам;
- `/users` — агенты и агентства из dataset `users-production`, видны в Studio только суперадминам.

Репозитории сайта и Studio остаются раздельными.

В workspace контента для `tour-to-date` доступно действие создания нового выезда на основе текущего документа. Оно копирует весь вариант тура и очищает даты и CRM-номер. Модель намеренно допускает отдельные программу, галерею, отели и другие детали для каждого выезда.

В карточке агента не отображаются служебные поля синхронизации с CRM и действие её повторного запуска. Сайт продолжает обрабатывать эти поля через webhook и ежедневный cron.

Пароли хранятся в объекте `{plain, hash}` согласно требованиям проекта. Studio не выполняет их автоматическое преобразование при переносе dataset.

## Конфигурация

Список переменных находится в `.env.example`.

`SANITY_STUDIO_SUPERADMIN_EMAILS` — список email существующих участников проекта Sanity с ролью `Administrator`, разделённых запятыми. Адреса сравниваются с email вошедшего пользователя без учёта регистра и пробелов по краям. После изменения переменной пересоберите Studio. Если список пуст или адрес не совпадает, дополнительные workspace и инструменты не показываются. Пароль пользователь вводит при обычном входе в Sanity; Studio не хранит ни пароль, ни его хэш.

На тарифе Sanity Free все сотрудники, редактирующие туры, должны иметь серверную роль `Administrator`. Инструмент «Сотрудники Studio» в `/site` показывает участников проекта и ожидающие приглашения, приглашает новых сотрудников с этой ролью, отзывает приглашения и удаляет обычных админов. Новый участник получает интерфейс обычного админа, пока его email не указан в `SANITY_STUDIO_SUPERADMIN_EMAILS`. Инструмент использует текущую сессию Sanity и не требует отдельного API-токена. Самого себя и любого суперадмина из списка удалить через инструмент нельзя.

Это разделение интерфейса, а не серверная защита: обладатель роли Sanity `Administrator` может обращаться к обоим dataset и настройкам проекта вне скрытых разделов Studio. Обычным админам не следует передавать `USER_DATA_MASTER_KEY`; его знание также не ограничивается интерфейсом Studio.

Поля профиля агента (email, названия компании, телефон, ЕДРПОУ, город, сайт и форма налогообложения) редактируются в Studio и доступны через API публичного dataset `users-production`. Список агентов использует название и email из этих полей; старые `displayName` и `displayIdentity` сохраняются для совместимости прежней версии Studio. У агентств по-прежнему открыты только `displayName` и `displayIdentity`. Пароли, CRM-идентификаторы и текст ошибки CRM остаются зашифрованными; служебный статус CRM открыт в документе, но скрыт в Studio.

```bash
npm run dev
npm run typecheck
npm run lint
npm run build
```
